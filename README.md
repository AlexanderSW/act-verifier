# act-verifier

Верифікатор актів виконаних робіт **КБ-2в / КБ-3**. Звіряє акт з договірною ціною та попередніми актами, видає вердикт, звіт з розбіжностями і блок доказів: що перевірено, що ні, звідки взято кожне число.

Агент готує акт, верифікатор його перевіряє, людина приймає рішення. Верифікатор нічого не виправляє і не пише у вхідні файли.

> Усі дані в репозиторії синтетичні. Компанії, договір і об'єкт вигадані.

## Вимоги

- Python **3.11+**
- Залежності: `openpyxl>=3.1`, `pandas>=2.1` (ставляться автоматично)
- Для розробки: `pytest>=8` (extras `dev`)

## Встановлення

**Windows (PowerShell):**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

**Linux / macOS:**

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

Після встановлення в середовищі з'являється команда `act-verifier`. Без встановлення пакета ту саму команду можна запустити як `python -m act_verifier.cli`, якщо `src` є в `PYTHONPATH`.

## Швидкий старт

Перевірити демо-акт №3 на синтетичних даних:

```bash
act-verifier \
  --contract data/synthetic/contract_boq.xlsx \
  --previous data/synthetic/act_01_2026-09.xlsx data/synthetic/act_02_2026-10.xlsx \
  --act data/synthetic/act_03_2026-11.xlsx \
  --out reports/
```

У PowerShell перенос рядка робиться знаком `` ` `` замість `\`, або команду можна записати в один рядок.

Вивід у консолі (блок доказів):

```text
## Блок доказів
Перевірено: 11 позицій × 7 перевірок рядка, 6 перевірок підсумків (виконано перевірок: 83).
Не перевірено: —
Джерела чисел:
- договірні ціни й обсяги — contract_boq.xlsx, аркуш «Договірна ціна», рядки 7–20
- попередні обсяги — act_01_2026-09.xlsx, аркуш «КБ-2в», рядки 2, 9–16; act_02_2026-10.xlsx, аркуш «КБ-2в», рядки 2, 9–19
- перевірюваний акт — act_03_2026-11.xlsx, аркуш «КБ-2в», рядки 2, 9–22; аркуш «КБ-3», рядки 5–8
Розбіжностей: 0. Вердикт: pass.
```

Код виходу `0`, а в `reports/` з'являються `act_03_2026-11_report.xlsx` і `act_03_2026-11_report.md`.

Щоб побачити акт з помилками, підставте в `--act` будь-який файл зі сценаріїв, наприклад `tests/fixtures/combo_three_errors/act_03.xlsx` (вердикт `fail`, код 1).

## Використання

```text
act-verifier --contract PATH --act PATH [--previous [PATH ...]] [--out DIR] [--journal [PATH]]
```

| Параметр | Обов'язковий | Що це | Типово |
| --- | --- | --- | --- |
| `--contract PATH` | так | договірна ціна (.xlsx, аркуш «Договірна ціна») | — |
| `--act PATH` | так | перевірюваний акт (.xlsx, аркуші «КБ-2в» і «КБ-3») | — |
| `--previous PATH ...` | ні | попередні акти 1…N−1 (.xlsx). Порядок не важливий: номер акта читається із заголовка «Акт № …», а не з назви файлу | немає |
| `--out DIR` | ні | тека для звіту, створюється, якщо її немає | `reports` |
| `--journal [PATH]` | ні | дописати знахідки `fail` / `unknown` / `warning` у журнал помилок | без параметра журнал не чіпається; `--journal` без шляху пише в `journal/agent_errors.csv` |

Для акта №1 попередні акти не потрібні. Якщо для акта N подано не всі акти 1…N−1, перевірки залишку (C05) і накопичувального підсумку КБ-3 (C13) стають `unknown`, а вердикт буде щонайкраще `needs_review`.

### Коди виходу

Агент, що готує акт, може орієнтуватися лише на код виходу, текст розбирати не потрібно.

| Код | Значення | Звіт | stdout | stderr |
| --- | --- | --- | --- | --- |
| `0` | `pass`: усі перевірки пройдено | пишеться | блок доказів | — |
| `1` | `fail`: є хоча б одна розбіжність | пишеться | блок доказів | — |
| `2` | `needs_review`: розбіжностей немає, але є `unknown` або `warning` | пишеться | блок доказів | — |
| `3` | помилка вхідних даних: перевірки не було | **не пишеться** | — | пояснення українською |

Код 3 означає, що вердикту немає. Причини:

- не задано `--contract` або `--act`, або задано невідомий параметр;
- файлу немає, або це не книга Excel;
- не знайдено обов'язковий аркуш, колонку заголовка чи підпис підсумку (`missing_label`);
- підпис неоднозначний, бо підходить кільком рядкам (`ambiguous_label`). Перший збіг ніколи не береться;
- шлях звіту або журналу збігається з вхідним файлом (`overwrite_refused`). Шляхи порівнюються повністю і без урахування регістру.

Помилкою вхідних даних **не** вважаються порожні клітинки кількості, ціни, вартості чи підсумку, нечитабельний номер акта і неповний набір попередніх актів. У цих випадках перевірка відбувається, а відповідні перевірки отримують статус `unknown`.

Зауваження: `--help` теж повертає 0, а неочікуваний виняток (баг) повертає 1, як у Python за замовчуванням.

### Вихідні файли

У теці `--out` створюються два файли, названі за іменем акта:

- **`<акт>_report.xlsx`**, аркуш «Перевірки». На кожну знахідку, зокрема `pass`, один рядок з колонками: шифр · перевірка · статус · очікувано · фактично · джерело.
- **`<акт>_report.md`**: знахідки і наприкінці блок доказів (той самий текст, що в консолі).

Повторний запуск на тому самому акті перезаписує ці файли. Звіт детермінований: на тих самих вхідних даних він дає ті самі знахідки й той самий блок доказів, без часових міток.

Тека `reports/` є в `.gitignore`.

### Журнал помилок

З прапорцем `--journal` кожна знахідка `fail`, `unknown` чи `warning` дописується рядком у CSV (знахідки `pass` не дописуються). Якщо файлу немає, він створюється із заголовком:

```csv
date,act_file,code,check,status,expected,actual,found_by,resolution
```

`found_by` завжди дорівнює `act-verifier`, а `resolution` лишається порожнім, його заповнює людина. Текст, що починається з `=`, `+`, `-` або `@`, отримує апостроф на початку (захист від формул в Excel). Журнал не впливає на код виходу.

## Формат вхідних файлів

Лоадер не прив'язаний до номерів рядків. Рядок заголовків таблиці він шукає за текстом колонок, а рядки підсумків за підписами. Підписи порівнюються після нормалізації: обрізаються пробіли на краях, кілька пробілів стають одним, регістр не враховується, збіг перевіряється за префіксом.

**Договірна ціна** (`contract_boq.xlsx`), аркуш «Договірна ціна»:

- колонки заголовка: «Шифр», «Найменування», «Од. виміру», «Кількість», «Ціна», «Вартість»;
- кожен шифр має траплятися один раз, дубль шифру дає `ambiguous_label`.

**Акт** (`act_*.xlsx`):

- аркуш «КБ-2в»:
  - над таблицею заголовок «Акт № N за … р.», з якого береться номер акта;
  - заголовок таблиці з тими самими колонками, що в договорі;
  - рядки позицій. Рядки без шифру, тобто порожні рядки й примітки, пропускаються і перелічуються в блоці доказів;
  - підсумки «Разом без ПДВ», «ПДВ», «Всього з ПДВ» зі значенням у колонці «Вартість».
- аркуш «КБ-3»: підписи «Вартість робіт за звітний період», «ПДВ», «Всього за звітний період», «З початку виконання робіт», біля кожного його значення.

Для попереднього акта обов'язкові лише аркуш «КБ-2в», колонки заголовка й «Всього з ПДВ».

Типова розкладка синтетичних файлів така: у договорі заголовки в рядку 6, дані з рядка 7; в акті шапка в рядках 1–6, заголовки в рядку 8, дані з рядка 9; у КБ-3 підписи в колонці A, значення в колонці B, рядки 5–8. Це лише приклад. Фікстура `shifted_header` перевіряє, що зсунутий заголовок теж читається.

**Числа.** Гроші й обсяги обробляються лише як `Decimal`, float в арифметиці не буває. Excel зберігає числа як float, тому значення читаються як `Decimal(str(value))`, а гроші округлюються до копійок (ROUND_HALF_UP). Порожня клітинка дає `None`, а не 0. Формула без збереженого значення вважається порожньою клітинкою. Файли відкриваються лише для читання (`data_only=True`).

## Перевірки

Повний каталог зі статусами, допусками й правилами пропуску є в [docs/checks.md](docs/checks.md).

| ID | Що перевіряє |
| --- | --- |
| C01 | шифр позиції є в договорі |
| C02 | одиниця виміру = договірна |
| C03 | ціна = договірна (0,00 грн) |
| C04 | вартість = кількість × ціна (±0,01) |
| C05 | кількість ≤ договір − Σ попередніх актів |
| C06 | шифр трапляється в акті один раз |
| C07 | «Разом без ПДВ» = Σ вартостей рядків |
| C08 | ПДВ = 20% від «Разом без ПДВ» |
| C09 | «Всього з ПДВ» = Разом + ПДВ |
| C10 | КБ-3 «Всього за звітний період» = КБ-2в «Всього з ПДВ» |
| C11 | кількість, ціна, вартість заповнені |
| C12 | в акті є хоча б одна позиція (інакше `warning`) |
| C13 | КБ-3 «З початку виконання» = Σ попередніх + поточний |

Статуси: `pass`, `fail` (з очікуваним і фактичним значенням), `unknown` (бракує даних, **ніколи не замінюється на `pass`**), `warning`.
Вердикт: `fail`, якщо є хоч один `fail`; `needs_review`, якщо є `unknown` або `warning`; інакше `pass`.

## Агент L1: Skill check-act

Ланка «агент» у ланцюжку «ШІ готує → код перевіряє → людина вирішує». Skill лежить у `.claude/skills/check-act/SKILL.md` і працює поруч з інструментом для агента (етап 2), а не замість нього.

**Як викликати.** Відкрийте сесію Claude Code у корені цього репозиторію (skill підхоплюється з `.claude/skills/`). Викличте `/check-act` або просто попросіть перевірити акт, назвавши файли: договірну ціну, попередні акти й сам акт, наприклад:

> Перевір акт `tests/fixtures/combo_three_errors/act_03.xlsx` — це акт 3. Договірна ціна — `data/synthetic/contract_boq.xlsx`, попередні акти — `data/synthetic/act_01_2026-09.xlsx` і `data/synthetic/act_02_2026-10.xlsx`.

Поки skill активний, без запиту дозволу запускається лише `.venv/Scripts/act-verifier` (`allowed-tools`, [ADR-0002](docs/features/check-act-skill/adr/0002-pre-allow-only-the-verifier-via-skill-allowed-tools.md)); будь-яка інша команда чи правка файлу запитає дозвіл. Інструкція описує виклик лише з цього репозиторію, без кроків встановлення на іншій машині.

**Що робить агент.** Питає про входи, яких людина не назвала, запускає верифікатор і пояснює його звіт у п'яти розділах: «Вердикт», «Знахідки», «Не перевірено», «Що зробити», «Звідки числа». Коли перевірки не було (код 3), каже про це й цитує повідомлення верифікатора.

**Чого агент не робить:**

- не рахує числа сам: усі числа беруться зі звіту верифікатора;
- не відкриває й не змінює вхідні файли;
- не вирішує, чи прийняти акт: рішення за людиною;
- не пише в журнал помилок, якщо людина не попросила.

Сценарій демо на трьох прикладах: [docs/features/check-act-skill/demo.md](docs/features/check-act-skill/demo.md).

## Розробка

### Тести

```bash
pytest -q
```

Робота вважається готовою, коли всі сценарії в `tests/test_verifier.py` зелені (без xfail) і `tests/test_fixtures_integrity.py` зелений.

| Файл | Що тестує |
| --- | --- |
| `test_verifier.py` | усі сценарії з `tests/fixtures` проти `expected.json` |
| `test_fixtures_integrity.py` | фікстури узгоджені з генератором і між собою |
| `test_cli.py`, `test_cli_unit.py` | CLI: коди виходу, звіти, журнал, захист вхідних файлів |
| `test_loaders.py`, `test_layout.py` | читання xlsx, пошук підписів |
| `test_checks.py`, `test_models.py`, `test_report.py` | перевірки, моделі, звіт і блок доказів |
| `test_check_act_skill.py` | skill check-act узгоджений з верифікатором: коди виходу, параметри команди, токен «перевірки не було», заголовок skill |

### Генерація синтетичних даних

```bash
python scripts/generate_fixtures.py
```

Скрипт є єдиним джерелом правди для `data/synthetic/*.xlsx` і `tests/fixtures/*`. Генерація детермінована. Перед записом скрипт **повністю видаляє** `tests/fixtures/` і створює теку заново.

### Правила репозиторію

Повна версія в [CLAUDE.md](CLAUDE.md). Коротко:

- гроші й обсяги обробляються тільки як `Decimal`;
- числа беруться лише з файлів, нічого не підставляється «за змістом»;
- якщо бракує даних, статус `unknown`, ніколи не `pass`;
- `expected.json` і xlsx у `tests/fixtures` не редагуються вручну, щоб тест «пройшов». Змінювати їх можна тільки через `scripts/generate_fixtures.py` і з поясненням чому;
- верифікатор лише читає вхідні файли;
- кожен звіт закінчується блоком доказів.
