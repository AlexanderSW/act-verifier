# Каталог перевірок

Кожна перевірка має стабільний ID. Він потрапляє у звіт, у журнал помилок і в `expected.json` фікстур.

## Статуси

| Статус | Значення |
| --- | --- |
| `pass` | Перевірено, збігається |
| `fail` | Перевірено, не збігається. Є очікуване й фактичне значення |
| `unknown` | Перевірити неможливо: бракує даних. **Ніколи не замінюється на `pass`** |
| `warning` | Арифметично не помилка, але людина має подивитися |

Вердикт акта: `fail`, якщо є хоч один `fail`; `needs_review`, якщо є `unknown` або `warning`; інакше `pass`.

## Перевірки рядків КБ-2в

| ID | Що перевіряє | Джерело еталона | Допуск |
| --- | --- | --- | --- |
| C01_position_in_contract | Шифр позиції є в договірній ціні | contract_boq.xlsx | точний збіг шифру |
| C02_unit_matches | Одиниця виміру = договірна | contract_boq.xlsx | точний збіг після `strip()` |
| C03_price_matches_contract | Ціна за одиницю = договірна | contract_boq.xlsx | 0,00 грн |
| C04_amount_arithmetic | Вартість = кількість × ціна | сам рядок | ±0,01 грн |
| C05_within_remaining_volume | Кількість ≤ договір − Σ попередніх актів | contract_boq.xlsx + act_01, act_02 | 0 |
| C06_no_duplicate_positions | Шифр трапляється в акті один раз | сам акт | — |
| C11_required_values_present | Кількість, ціна, вартість заповнені | сам рядок | — |

Правила пропуску:
- якщо C01 = `fail`, перевірки C02, C03, C05 для рядка не виконуються (нема з чим звіряти);
- якщо C11 = `unknown`, перевірки, яким бракує значення, не виконуються:
  - порожня ціна → C03 і C04 не виконуються (причина «порожня ціна»), ціна не підставляється;
  - порожня кількість → C04 і C05 не виконуються;
  - порожня вартість → C04 не виконується, а C07 = `unknown` з назвою позиції, якій бракує вартості;
- формула без збереженого значення вважається порожньою клітинкою (не 0 і не обчислюється).

У кожному з цих випадків вердикт — щонайкраще `needs_review`, ніколи не `pass`.
Пропущені перевірки потрапляють у розділ «що не перевірено» блоку доказів. Туди ж потрапляє кожна перевірка зі статусом `unknown` через брак даних (порожнє значення в договорі, у попередньому акті чи в надрукованих підсумках, неповний набір попередніх актів) — з позицією і тією самою причиною. Виняток — сама C11: вона виконана, а пропущені нею перевірки вже стоять у списку.

## Перевірки підсумків і КБ-3

| ID | Що перевіряє | Допуск |
| --- | --- | --- |
| C07_subtotal | «Разом без ПДВ» = Σ вартостей рядків | ±0,01 грн |
| C08_vat | ПДВ = 20% від «Разом без ПДВ» | ±0,01 грн |
| C09_total_with_vat | «Всього з ПДВ» = Разом + ПДВ | ±0,01 грн |
| C10_kb3_matches_kb2v | КБ-3 «Всього за звітний період» = КБ-2в «Всього з ПДВ» | ±0,01 грн |
| C12_act_not_empty | В акті є хоча б одна позиція (інакше `warning`) | — |
| C13_kb3_cumulative | КБ-3 «З початку виконання» = Σ «Всього з ПДВ» попередніх актів + поточний | ±0,01 грн |

Перевірки підсумків порівнюють із **надрукованими** в акті значеннями, а не з перерахованими:
C08 бере надруковане «Разом без ПДВ»; C09 — надруковані «Разом без ПДВ» і ПДВ; C10 — надруковане
КБ-2в «Всього з ПДВ»; C13 — Σ надрукованих КБ-2в «Всього з ПДВ» попередніх актів + надруковане
поточне «Всього з ПДВ». Тому неправильне «Разом без ПДВ» дає лише C07 `fail`.

Порожнє надруковане значення (підпис є, клітинка значення порожня) — це брак даних, а не помилка
вхідних даних: кожна перевірка, якій воно потрібне, стає `unknown` з назвою значення:

| Порожнє значення | `unknown` |
| --- | --- |
| «Разом без ПДВ» | C07, C08, C09 |
| «ПДВ» | C08, C09 |
| «Всього з ПДВ» | C09, C10, C13 |
| КБ-3 «Всього за звітний період» | C10 |
| КБ-3 «З початку виконання робіт» | C13 |
| «Всього з ПДВ» попереднього акта | C13 |

## Попередні акти

- Номер акта N (поточного й попередніх) читається лише з заголовка КБ-2в, нормалізований текст якого
  починається з «Акт №». Назва файлу й текст КБ-3 «до акта №» не використовуються. Номера немає або
  він не число — це брак даних, а не помилка вхідних даних.
- Попередні акти мають бути рівно 1…N−1. Інакше C05 **кожної** позиції і C13 = `unknown` з причиною,
  решта перевірок виконується, вердикт — щонайкраще `needs_review`:
  - «номер акта не прочитано» — N поточного акта невідомий;
  - «номер попереднього акта не прочитано — <файл>»;
  - «повторюється номер попереднього акта M»;
  - «номер попереднього акта M поза 1…N−1» (зокрема сам N);
  - «подано попередніх актів: K з N−1», де K — кількість різних номерів у межах 1…N−1 (зокрема 0).
- Порожня кількість позиції в попередньому акті → C05 цієї позиції = `unknown`.
- Шифр, що повторюється в одному попередньому акті, підсумовується (C06 — лише для поточного акта).

## Помилка вхідних даних (код 3)

Перевірки не було: немає вердикту й не пишеться звіт. Повідомлення називає, чого саме бракує.

- Підпис розкладки не знайдено (аркуш, колонки заголовка, підписи підсумків КБ-2в, чотири підписи КБ-3;
  для попереднього акта — аркуш «КБ-2в», колонки заголовка й «Всього з ПДВ»). Підписи шукаються після
  нормалізації (обрізання, будь-які пробіли в один, без регістру) за префіксом; ПДВ не вимагає «20%».
- Підпис неоднозначний: після нормалізації йому відповідає більше одного рядка. Перший збіг не
  використовується ніколи; повідомлення називає рядки-кандидати.
- Шифр повторюється в договірній ціні: позиція неоднозначна, не береться ні перший, ні останній рядок;
  повідомлення називає шифр і рядки. (Порожня кількість чи ціна в договорі — не помилка вхідних даних, а
  брак даних: C05 чи C03 цієї позиції = `unknown`.)
- Файл не читається як книга Excel або його немає.
- Помилка виклику: не задано договірну ціну чи перевірюваний акт або задано невідомий параметр
  (попередні акти необов'язкові).
- Відмова писати у вхідний файл: шлях звіту або журналу збігається з одним із вхідних файлів
  (повні шляхи без урахування регістру). Верифікатор ніколи не пише у свої вхідні файли.

## Блок доказів (обов'язковий наприкінці кожного звіту)

```markdown
## Блок доказів
Перевірено: 11 рядків × 7 перевірок, 6 перевірок підсумків.
Не перевірено: 5-2 — C03, C04 (порожня ціна).
Джерела чисел:
- договірні ціни й обсяги — contract_boq.xlsx, аркуш «Договірна ціна», рядки 7–20
- попередні обсяги — act_01_2026-09.xlsx, act_02_2026-10.xlsx, аркуш «КБ-2в»
- перевірюваний акт — act_03.xlsx, аркуші «КБ-2в», «КБ-3»
Розбіжностей: 1 fail, 1 unknown. Вердикт: fail.
```

## Наступні сценарії (ще не в фікстурах)

- число записане текстом («1 250,50»);
- шифр з пробілом або іншим дефісом («2‑1» з нерозривним дефісом);
- нульова кількість у рядку;
- накопичувальний підсумок КБ-3 не збігається (C13 `fail`).
